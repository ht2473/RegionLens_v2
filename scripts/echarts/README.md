# Урезанная сборка библиотеки графиков

`static/vendor/echarts.min.js` — не дистрибутив с сайта библиотеки, а сборка из её
частей: в работе используются пять построений из сорока, а географический слой,
самая крупная часть полного файла, не нужен вовсе — картограмма рисуется на сервере
разметкой SVG.

Сборка одноразовая и в цикл разработки не входит. Ни `node_modules`, ни `package.json`
в репозитории нет: собранный файл лежит готовым, как и все остальные сторонние файлы
в `static/vendor/`.

## Как пересобрать

Нужны Node.js 20 или новее и сеть — один раз.

```bash
mkdir echarts-build && cd echarts-build
npm init -y
npm install echarts@6.1.0 esbuild
cp ../scripts/echarts/entry.js .
npx esbuild entry.js --bundle --minify --format=iife --global-name=echarts --legal-comments=none --target=es2018 --outfile=../static/vendor/echarts.min.js
```

Точка сборки копируется в каталог сборки не для удобства: разбор имён вроде
`echarts/core` идёт вверх по дереву от самого файла, и точка, оставленная
в репозитории, искала бы `node_modules` там, где их нет и быть не должно.

Каталог сборки после этого удаляется.

## Что получилось

| | Размер | Он же сжатым |
|---|---|---|
| Полный дистрибутив 5.6 | 1 010 КБ | 327 КБ |
| Сборка из частей, 5.6 | 591 КБ | 196 КБ |
| Сборка из частей, 6.1 (17.09.2026) | 629 КБ | 213 КБ |
| Та же с отрисовкой SVG, 6.1 (05.10.2026) | 650 КБ | 221 КБ |

Ниже не опуститься: одно только ядро библиотеки — система координат, слой отрисовки
и разбор настроек — занимает 437 КБ, и это проверено сборкой с единственным
построением. Части, добавленные сверх ядра, дают 154 КБ, и все они используются.
Оценка «250–300 КБ», записанная при планировании этапа, была занижена: она не учитывала
неделимого ядра.

## Что делать, если график перестал рисоваться

Скорее всего в настройках появилось построение или часть холста, которых нет
в `entry.js`: библиотека, собранная по частям, о незарегистрированном построении
молчит — в консоли браузера остаётся предупреждение вида `Series ... is not exists`.
Допишите нужное в `entry.js` и пересоберите.

Перечень частей сверен с настройками, собираемыми в `apps/core/charts.py`
и `apps/analytics/charts.py`.

## Переход на ECharts 6 (17.09.2026)

Состав частей прежний. Что изменилось в библиотеке и как это учтено:

- **`grid.containLabel` объявлен устаревшим.** В сборке по частям его старая
  раскладка есть только с частью `LegacyGridContainLabel`; без неё библиотека
  выполняет `containLabel: true` новым механизмом `outerBounds` с границей по полю
  графика и подписям осей — это и нужно. Старая часть в сборку не включена.
- **Новая тема по умолчанию** (палитра, оттенки осей). Палитра рядов, шрифты,
  подсказка и оси задаются из маркеров оформления (`baseOptions` в `static/js/lib/chart-options.js`),
  поэтому на облик влияют только незаданные мелочи. Тему `v5` не подключаем:
  облик графиков пересобирается на шаге 5 модернизации.
- Сборка прибавила 38 КБ (сжатой — 16 КБ): это новое ядро раскладки осей.

## Отрисовка SVG (05.10.2026)

Графики на странице рисуются холстом, но картинка графика сохраняется и файлом SVG — для
вёрстки материала и курсовой. Для этого в сборку добавлена часть `SVGRenderer` (+21 КБ,
сжатой +8 КБ): `static/js/elements/chart.js` строит второй экземпляр графика с векторной
отрисовкой в невидимом узле и берёт разметку `renderToSVGString()`. Строковый вывод
библиотеки вписывает семейство шрифта в атрибут без экранирования, поэтому перед этим
кавычки в `fontFamily` заменяются одинарными.
